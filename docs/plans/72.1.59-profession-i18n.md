# План 72.1.59 — вынос текстов профессий из YAML в i18n

**Статус:** в работе
**Дата:** 2026-05-05
**Контекст:** baseline после плана 72.1.58 (`d07d0fc4bf feat(profession): план
72.1.58 — ProfessionScreen 1:1 с legacy`).

## Проблема

В [projects/game-nova/configs/professions.yml](../../projects/game-nova/configs/professions.yml)
балансовый конфиг хранит **языковые строки** (русский UI):

```yaml
professions:
  universal:
    label: "Универсал"
    description: "Универсал не имеет специализации, …"
  miner:
    label: "Шахтер"
    description: "Шахтер специализируется на добыче ресурсов"
  …
```

Это нарушает архитектурное правило проекта:
- Балансовые YAML — источник истины для **числовых** параметров (cost, time,
  bonus/malus). Тексты (label/description) живут в [configs/i18n/{ru,en}.yml](../../projects/game-nova/configs/i18n/).
- Аналогичные сущности — здания, исследования, юниты — имеют только
  численные параметры в `*.yml`, а имена и описания — в `info.<key>` /
  `info.<key>Desc` / `info.<key>FullDesc` группе i18n (см.
  [configs/i18n/ru.yml:2317+](../../projects/game-nova/configs/i18n/ru.yml#L2317)).
- Поддержка английской локали невозможна без правки YAML и без перевода
  `description`. Сейчас `Profession.description` уйдёт в JSON английскому
  игроку как русский текст — bug по факту.

Также `Service.labelFor()` в
[backend/internal/profession/service.go:247-255](../../projects/game-nova/backend/internal/profession/service.go#L247-L255)
вызывается с параметром `lang i18n.Lang`, но возвращает `spec.Label` —
**игнорирует язык** для всех ключей кроме `none`. AutoMsg
`creditProfessionChanged` английскому юзеру подставит русский «Шахтер».

## Цель

Вынести `label`/`description` из `professions.yml` в i18n-словари,
переведя по ходу на en. После — `professions.yml` содержит только
балансовые поля, как у buildings/research/ships.

## Дерево правок

### Ф.1 i18n-словари (источник правды для UI-текстов)

[configs/i18n/ru.yml](../../projects/game-nova/configs/i18n/ru.yml) — в группу
`profession:` (после `errGeneric`) добавить:

```yaml
  # Названия и описания профессий 1:1 с legacy oxsar2 sql/new-for-dm/data.sql
  # ключи PROFESSION_UNKNOWN/_MINER/_ATTACKER/_DEFENDER/_TANK + _DESC.
  # Был в configs/professions.yml — вынесено в i18n планом 72.1.59.
  universalLabel: Универсал
  universalDesc: Универсал не имеет специализации, все постройки и исследования работают в нормальном режиме
  minerLabel: Шахтер
  minerDesc: Шахтер специализируется на добыче ресурсов
  attackerLabel: Атакер
  attackerDesc: Специализируется на атаках
  defenderLabel: Оборонщик
  defenderDesc: Специализируется на обороне
  tankLabel: Танкист
  tankDesc: Специализируется на пробивной мощи
```

[configs/i18n/en.yml](../../projects/game-nova/configs/i18n/en.yml) — те же
ключи с английскими переводами:

```yaml
  universalLabel: Universal
  universalDesc: Universal has no specialization, all buildings and research work in normal mode
  minerLabel: Miner
  minerDesc: Miner specializes in resource extraction
  attackerLabel: Attacker
  attackerDesc: Specializes in attacks
  defenderLabel: Defender
  defenderDesc: Specializes in defense
  tankLabel: Tank
  tankDesc: Specializes in penetrating power
```

Ключи именуются `<key>Label` / `<key>Desc` (а не вложенный объект
`<key>.label`) — у `i18n.Bundle.Tr(group, key, ...)` плоский namespace
внутри группы, точечный путь не поддерживается.

[configs/professions.yml](../../projects/game-nova/configs/professions.yml):

- обновить заголовочный комментарий: убрать упоминание «label/description

После правки записи будут вида:

  bundle = nil (graceful degradation, как было раньше) — возвращаем
  `key`. Это устраняет независимый bug 72.1.59:
  AutoMsg-уведомление о смене профессии теперь действительно

## Risk / regressions

- **API-break `/api/professions` и `/api/professions/me`.** Поля
  `label`, `description` исчезают. Старые клиенты ломаются. Origin-
  фронт правится в этом же плане; legacy nova-фронт (если использует
  эти поля) — не использует, проверено `grep -r "professions/me" frontends/nova`.
- **Тесты-снапшоты.** Если где-то есть golden-фикстуры с JSON-ответом
  `/api/professions` — регенерировать. На дату 72.1.58 таких нет.
- **AutoMsg locale.** `creditProfessionChanged.body` теперь получит
  правильно переведённое имя профессии — поведение **меняется в
  лучшую сторону** для en-юзеров. Это закрывает скрытую дыру.
