## Контекст и цель

Реализовать «Автопилот» — детерминированную rule-based систему, которая знает
всё состояние игрока (ресурсы, здания, флот, планеты, очередь событий, соседи)
и все внутренние игровые формулы (производство, стоимости, время, бой,
экспедиции, шпионаж). Автопилот вычисляет топ-3 оптимальных хода и предлагает
их игроку. Игрок подтверждает — событие создаётся автоматически через
стандартные сервисные методы, фронт навигирует на целевой экран.

Автопилот представлен в UI как одна из «моделей» в виджете советника (наряду
с LLM Haiku / Sonnet / Opus). В отличие от LLM — не отвечает на вопросы
в свободной форме, только предлагает конкретные ходы.

**Стоимость**: 2 кр за запрос (конфиг `AutopilotCostCredits`), списывается
при постановке задания в очередь.

**Расчёт в воркере**: тяжёлый snapshot + scoring вынесен в event kind
`KindAutopilotAdvise`, чтобы не блокировать HTTP. Результат доставляется
через WebSocket (`autopilot_ready`); до появления WS-инфраструктуры —
polling fallback раз в 2 сек.

## Что умеет Автопилот

Предлагает **любое действие, доступное игроку**:

| Категория | Действия |
|---|---|
| Строительство | Постройка/апгрейд здания на планете |
| Исследования | Запуск исследования технологии |
| Флот | Постройка кораблей на верфи |
| Оборона | Постройка оборонных установок |
| Миссии | Атака, шпионаж, транспорт, экспедиция, колонизация, переработка обломков |
| ACS | Присоединиться к чужой атаке |
| Экономика | Транспорт ресурсов между планетами; обмен на бирже артефактов |
| Профессия | Активировать/сменить офицера |

## Стратегии оптимизации

Игрок задаёт стратегию в виджете (хранится в профиле):

| Стратегия | Что оптимизируется |
|---|---|
| **Экономика** | Максимальный прирост производства ресурсов (score/час) |
| **Военная** | Максимизация боевой мощи флота |
| **Оборона** | Максимизация оборонных установок и защитных технологий |
| **Экспансия** | Скорейшая колонизация новых планет |
| **Авто** | Советник сам выбирает по фазе развития |

Режим **Авто** — эвристика фазы:
- Нет 3-й планеты → Экспансия
- Производство < порога → Экономика
- Флот слабее среднего по галактике → Военная
- Иначе → Оборона

## Алгоритм выбора хода

1. **buildSnapshot** — собрать PlayerSnapshot:
   - `planet.Service.ListByUser(ctx, userID)` → список планет с ресурсами
   - `planet.Service.Forecast(ctx, planetID, 1)` → ресурсы через 1 час
   - здания и уровни из Planet.Buildings
   - `research.Service` → текущие технологии
   - `fleet.Service` → флоты дома + в полёте
   - активные события из event queue (building/research в очереди)
   - активные офицеры из profession
   - `score.Service.PlayerScore(ctx, userID, "total")` → текущие очки
   - соседи из galaxy: userID → координаты → список планет в радиусе → их сила

2. **scoreCandidates** — для каждого доступного действия рассчитать выгоду:
   - Строительство/исследование: `delta_score / build_time_seconds`
     (delta_score = разница очков до/после по формулам `score.Service`)
   - Атака: ожидаемый грабёж (battle.Simulator.Simulate) минус ожидаемые потери
   - Экспедиция: мат. ожидание по таблице экспедиций из `configs/`
   - Шпионаж: `spy_success_prob` = f(уровень_шпионажа_атак - уровень_шпионажа_защ)
   - Транспорт ресурсов: выгода = дефицит на целевой планете
   - Флот/оборона (военная стратегия): `delta_military_score / build_time`

3. **Топ-3** — три кандидата с максимальным score, разных категорий если возможно.

4. **Валидация при Execute** — перепроверить доступность прямо перед созданием
   события (ресурсы не ушли, слот не занят, флот не улетел).

## Фаза Ф.2: Миссии (атака, шпионаж, транспорт, экспедиция)

Расширить `scoreCandidates` категориями:

**Атака** (`category="attack"`):
- Перебрать соседей из `snap.Neighbors` с militaryScore < snap.MilitaryScore * 0.8
- Для каждого: `battle.Simulator.Simulate(attackFleet, defenseFleet)` → ожидаемый грабёж
- Score = ожидаемый_грабёж_в_очках - ожидаемые_потери_в_очках
- Params: `{mission: "attack", target_planet_id, fleet_composition}`

**Шпионаж** (`category="spy"`):
- Соседи без актуального отчёта шпионажа (> 1 часа)
- Score = `spy_success_prob * info_value`; prob = sigmoid(spy_lvl_att - spy_lvl_def)
- Params: `{mission: "spy", target_planet_id, probes_count}`

**Транспорт** (`category="transport"`):
- Если на планете профицит ресурса > 50% capacity, а на другой дефицит
- Score = дефицит_в_очках / transit_time
- Params: `{mission: "transport", src_planet_id, dst_planet_id, resources}`

**Экспедиция** (`category="expedition"`):
- Если есть свободный флот и слот экспедиции
- Score = мат_ожидание_награды / expedition_time (по таблице из `configs/`)
- Params: `{mission: "expedition", planet_id, fleet_composition, duration}`

В `Execute` для миссий вызывать `fleet.TransportService.Send(ctx, TransportInput{...})`.

`hub.Broadcast` уже используется в `chat/hub.go`. Автопилот использует тот же
механизм через `Channel: "user:" + userID`. Ф.6 означает только подключение
фронта к существующему WS-соединению и подписку на `type="autopilot_ready"`.
До появления WS на фронте работает polling из Ф.1.

## Правила реализации

- Все IO-методы принимают `ctx context.Context` первым параметром.
- SQL — только через `pgx` напрямую, без sqlc. Параметризованные запросы.
- Ошибки оборачивать: `fmt.Errorf("autopilot.Compute: %w", err)`.
- Никакого `panic` в прод-коде.
- Новые Go-файлы — пакет `aiadvisor`, не создавать отдельный пакет.
- Тесты обязательны для `scoreCandidates` и `Enqueue`/`Compute`.
- OpenAPI (`projects/game-nova/api/openapi.yaml`) обновить новыми эндпоинтами.
- `docs/simplifications.md` — записать если что-то упрощено относительно плана.

## Отложено: режим «Полный автопилот»

Режим, при котором Автопилот выполняет ходы **без подтверждения игрока**
(пока тот офлайн) — отдельный тарифный план, отдельный план разработки.
В этот план не входит.
